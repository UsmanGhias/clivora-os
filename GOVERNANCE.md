# CLIVORA Governance

CLIVORA uses open contribution with accountable maintainership.

## Roles

### Community participants

Anyone may use public channels, report issues, propose ideas, review work, improve documentation, test releases, or submit a contribution.

### Contributors

Contributors have accepted work in the project. Contributions are evaluated on merit, safety, maintainability, product value, and compliance with project policies.

### Maintainers

Maintainers review contributions, manage releases, protect quality, and enforce community standards. Maintainer status is earned through sustained, trusted contribution and may be changed when responsibilities are not met.

### Project lead

**Usman Ghias** is the founder, copyright holder for his original work, and initial project lead. The project lead appoints maintainers and has final responsibility for security, legal compliance, production access, trademarks, releases, and unresolved product decisions.

## Decision process

1. Normal fixes and small improvements are decided in pull-request review.
2. Large features, breaking changes, governance changes, and architecture decisions should begin with a public issue or request for comments.
3. Maintainers seek practical consensus using evidence, user impact, tests, privacy, security, and long-term maintenance.
4. If consensus cannot be reached, the project lead records a final decision and rationale.

Community feedback materially influences the roadmap, but no vote can require an insecure, unlawful, deceptive, unfunded, or operationally unsustainable change.

## Transparency

Roadmap work, public product decisions, and contribution review should happen in public repository channels whenever privacy and security allow. Security reports, personal data, production credentials, commercial negotiations, and legal matters remain private.

## Releases and production

Only explicitly authorized maintainers may approve releases. Repository contribution does not grant production, database, domain, app-store, payment, email, or infrastructure access.

## Licence and copyright

Code is accepted under AGPLv3. Each contributor retains copyright in original contributions while licensing them to the public under AGPLv3. Project trademarks and official identity remain separate from the code licence.

## Changes to governance

Material governance changes should be proposed publicly and documented through a reviewed pull request. The project lead approves the final policy.
